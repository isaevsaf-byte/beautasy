# Ночная копия Sanity

## Что это

Каждую ночь в 02:17 по UTC (03:17 по Лондону летом, 02:17 зимой) маленький
робот на Cloudflare забирает из Sanity всё содержимое сайта — товары и цены,
дневник записей, отзывы, партнёров, «Кассу», настройки — и кладёт одним файлом
в закрытое хранилище R2. R2 — это как Dropbox, только у Cloudflare.

Один файл на ночь. Хранятся последние 30 ночей, более старые робот удаляет сам.

Зачем: у Sanity на бесплатном тарифе своих копий нет. Если кто-то или
какой-то скрипт сотрёт данные, вернуть их было бы неоткуда. Это запасной ключ
от квартиры, который лежит у соседа.

Сколько стоит: ничего. Файл сейчас около 0,6 МБ, тридцать штук — 18 МБ,
а бесплатно R2 даёт 10 ГБ.

## Что в копии есть и чего нет

- **Есть** все документы, включая черновики (то, что начали и не опубликовали).
- **Зашифрованные поля** (телефоны, почты, коды) лежат в копии тоже
  зашифрованными. 🚨 Прочитать их можно только тем же ключом `DATA_SECRET`.
  Ключ потерян — эти поля в копии бесполезны. Ключ должен жить в менеджере
  паролей и на бумаге, не только в Vercel.
- **Картинок нет.** В копии есть их описания (имя, размер, адрес), а сами
  файлы живут у Sanity. Если сотрут документы — картинки останутся на месте,
  и восстановление их подхватит. Если удалят весь датасет или проект —
  картинки пропадут вместе с ним, и их придётся загружать заново.
- 🚨 **Имена клиентов в копии лежат открытым текстом.** Хранилище закрытое,
  и так должно остаться: публичный доступ к нему не включать. Скачанную
  копию не класть в папку проекта (репозиторий публичный) и удалять после
  работы.

## Включить (один раз)

Все команды — из папки этого робота:

```
cd ~/Projects/Beautasy/workers/sanity-backup
```

1. Проверить, что вход в Cloudflare есть: `npx wrangler whoami`.
   Если нет — `npx wrangler login`.
2. Создать хранилище в ЕС (`--location weur` Cloudflare может не
   послушать — 03.10 так оно оказалось в США; `--jurisdiction eu` держит
   данные в ЕС наверняка):

   ```
   npx wrangler r2 bucket create beautasy-backups --jurisdiction eu
   ```

3. Убедиться, что оно закрыто — ответ должен быть, что публичный доступ
   выключен (disabled):

   ```
   npx wrangler r2 bucket dev-url get beautasy-backups --jurisdiction eu
   ```

4. (Можно позже.) Без токена копия берёт все опубликованные документы —
   заказы, дневник, кассу, — но не черновики. С токеном — и черновики.
   Сделать токен в Sanity: sanity.io/manage → проект Beautasy → API →
   Tokens → Add API token. Имя `Cloudflare backup`, права **Viewer**
   (только чтение). Sanity покажет токен один раз — скопировать.
   Токен отдельный, свой: если что, его можно отозвать, не трогая сайт.
5. Выложить робота:

   ```
   npx wrangler deploy
   ```

6. Отдать роботу токен. Команда спросит значение — вставить токен, Enter.
   В саму команду токен не писать:

   ```
   npx wrangler secret put SANITY_READ_TOKEN
   ```

7. На следующее утро проверить, что копия появилась (см. ниже).

## Как понять, что копии делаются

- Cloudflare → R2 → `beautasy-backups` → папка `sanity/` → файл
  `production-ГГГГ-ММ-ДД.ndjson` с сегодняшней датой.
- Cloudflare → Workers → `beautasy-sanity-backup` → Logs. Строка вида
  `{"saved":"sanity/production-2026-10-04.ndjson","documents":251,"bytes":580462,"drafts":false}`.
  `drafts: false` — копия без черновиков (токена нет, шаги 4 и 6).
  `documents` — сколько документов в копии. Если число резко упало (было
  250, стало 20) — что-то стёрли, смотреть сразу: старые копии целы ещё
  30 дней.
- Ночь не удалась — запуск помечен ошибкой, новая копия не сохранена,
  старые не тронуты.

Тревогу никто не пришлёт: если робот тихо перестанет работать, это видно
только в R2. Раз в неделю глянуть, что свежий файл на месте.

Что значат ошибки в логах:

| Ошибка | Что случилось | Что делать |
|---|---|---|
| `answered 401` или `403` | Токен отозван или неверный | Новый токен: шаги 4 и 6 |
| `answered 404` | Неверный проект или датасет | Проверить `vars` в `wrangler.jsonc` |
| `incomplete` или ошибка сети (`Network connection lost` и похожие) | Sanity оборвал выгрузку на середине | Обычно разовое, следующей ночью повторит. Несколько ночей подряд — разбираться |
| `empty` | Sanity отдал пустой датасет | Срочно смотреть, что с данными |
| `exceeded CPU` | Данных стало много для бесплатного тарифа Workers | Платный Workers, $5 в месяц |

## Восстановление

### Пропал или испорчен один документ

Сначала Studio: открыть документ → история правок (значок часов) → вернуть
нужную версию. Sanity сам помнит правки за последние дни. Если документ
удалён целиком или прошло больше времени — тогда копия, по шагам ниже.

### Шаг 1. Скачать копию

Скачивать в отдельную папку, не в проект:

```
mkdir -p ~/beautasy-restore
cd ~/Projects/Beautasy/workers/sanity-backup
npx wrangler r2 object get beautasy-backups/sanity/production-2026-10-03.ndjson --remote --file ~/beautasy-restore/production-2026-10-03.ndjson
```

Дату в имени поставить нужную. `--remote` обязателен: без него wrangler
ищет в пустой локальной копии и говорит, что файла нет. Какие даты есть,
видно в Cloudflare → R2 → `beautasy-backups` → `sanity/`. Там же файл можно
скачать кнопкой Download.

### Шаг 2. Проверить копию в новом датасете — всегда сначала так

Из корня проекта (там записан номер проекта Sanity):

```
cd ~/Projects/Beautasy
npx sanity login
npx sanity dataset create restore-test
npx sanity dataset import ~/beautasy-restore/production-2026-10-03.ndjson restore-test --allow-assets-in-different-dataset
```

`--allow-assets-in-different-dataset` нужен, потому что описания картинок
в копии указывают на датасет `production`. Сами картинки в `restore-test`
могут не показываться — для проверки это нормально.

На бесплатном тарифе Sanity новый датасет будет публичным, как и
`production`: черновики и зашифрованные поля закрыты так же. Но держать его
дольше проверки незачем. Датасетов на бесплатном тарифе всего два — если
`create` откажет, сначала удалить старый `restore-test`.

Сверить, что документов столько же:

```
npx sanity documents query 'count(*)' --dataset production
npx sanity documents query 'count(*)' --dataset restore-test
npx sanity documents query 'count(*[_type == "product"])' --dataset restore-test
```

Числа должны совпасть или почти совпасть — если после ночи копии что-то
добавили или удалили.

Удалить проверочный датасет:

```
npx sanity dataset delete restore-test
```

🚨 Он попросит вписать имя для подтверждения. Вписать `restore-test`.
Никогда не `production`.

### Шаг 3. Вернуть в production — только после шага 2

Сначала снимок того, что есть сейчас, на случай ошибки:

```
npx sanity dataset export production ~/beautasy-restore/before-restore.tar.gz
```

Потом вернуть только пропавшие документы, ничего существующего не трогая:

```
npx sanity dataset import ~/beautasy-restore/production-2026-10-03.ndjson production --missing
```

`--missing` значит «добавь то, чего нет; что есть — не трогай». Всё, что
поменяли после ночи копии, останется.

🚨 Не запускать с `--replace`: он перепишет всё, что изменилось после ночи
копии, — новые записи, оплаты в «Кассе», правки Кристины. Только если весь
датасет испорчен и это осознанное решение после снимка выше.

Если удалён весь датасет: сначала `npx sanity dataset create production`,
потом импорт как выше, добавив `--allow-failing-assets`. Документы вернутся,
картинки придётся загрузить заново.

### Шаг 4. Убрать за собой

Удалить папку `beautasy-restore` в Finder и очистить корзину. В ней имена
клиентов.

## Поменять настройки

- Время запуска — `crons` в `wrangler.jsonc` (время UTC).
- Сколько дней хранить — `KEEP_DAYS` в `src/backup.ts`.
- После правок: `npx wrangler deploy` из этой папки.

## Как устроено внутри

- Sanity отдаёт выгрузку потоком и заранее не говорит размер, а R2 без
  размера файл не примет. Поэтому робот режет поток на куски по 5 МБ и
  отправляет кусками. Пока данных меньше 5 МБ (сейчас около 0,6 МБ) — уходит
  одним файлом. Целиком в памяти выгрузка не держится никогда.
- Перед сохранением робот проверяет, что последняя строка — целый документ.
  Когда у Sanity сбой посреди выгрузки, ответ уже ушёл как «200 OK», и сбой
  виден только по оборванной последней строке или по ошибке, дописанной в
  конец. Такая копия не сохраняется, старые не удаляются.
- Старые копии удаляются только после того, как сегодняшняя легла.
  Поэтому череда неудачных ночей не может вычистить хранилище.
- В лог попадают только имя файла, число документов и размер. Ни токена,
  ни содержимого.
- Проверки — `src/lib/sanityBackup.test.ts` в корне проекта, идут вместе со
  всеми тестами (`npm test`).
